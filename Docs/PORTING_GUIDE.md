# Calendar iOS — Обзор проекта и план портирования

Документ фиксирует текущее состояние обоих проектов (`Calendar` на Android/Kotlin и `CalendarIos` на iOS/Swift), расхождения по функциональности, схему данных и рекомендации по нативной iOS-реализации.

---

## 1. Общая картина

- **Референс (`Calendar`)** — релизное Android-приложение на Kotlin + Jetpack Compose + Material 3, локальная БД Room (12 таблиц, версия 22), облачная синхронизация Firebase Auth/Firestore + FCM, локальные уведомления, бэкап в Google Drive, реклама AdMob, встроенные туториалы и локализация на 7 языков (`en`, `ru`, `es`, `de`, `pt`, `fr`, `it`).
- **Целевой проект (`CalendarIos`)** — iOS 17+ приложение на Swift 6 + SwiftUI + GRDB (SQLite), управление проектом через XcodeGen (`project.yml`) + `Package.swift` (`CalendarIosCore`).
- **Цель** — создать полноценную iOS-версию, близкую по возможностям и UX-сценариям к Android-версии, но оформленную и спроектированную с учётом нативных паттернов iOS (HIG, SF Symbols, системные пикеры, жесты, iCloud/EventKit/Contacts/Photos и т.д.).

## 2. Что уже сделано в `CalendarIos`

### Инфраструктура и слой данных
- `AppDatabase` + `DatabaseMigratorFactory` на GRDB (`calendar.sqlite` в Application Support, есть `inMemory()` для превью и тестов).
- Миграция `v1_event_types_and_events`: таблицы `event_types` и `events`.
- Доменные модели: `CalendarEvent`, `EventDraft`, `EventType`, `WeekDaySection`.
- Репозиторий `GRDBEventRepository` (CRUD событий, чтение типов, сидирование 3 тестовых типов и 3 событий при пустой БД).

### UI и навигация
- `AppShellView` — базовая оболочка с переключением режимов (`day` / `week` / `month`), кнопкой меню (`sheet` со списком заглушек разделов).
- `WeeklyView` + `WeeklyViewModel` — **самая проработанная часть**:
  - Непрерывный горизонтальный скролл по дням с динамической подгрузкой диапазонов (`ensureLoaded`).
  - Закреплённая шкала часов слева (`TimeColumnView`) и шапки дней сверху (`WeeklyDayHeader`).
  - Расчёт пересекающихся событий в колонки (`WeeklyTimelineEventLayout`).
  - Двухосевой pinch-to-zoom (ширина колонки дня + высота часа) и кнопки вертикального зума (`+`, `-`, весь день).
  - Долгое нажатие по пустому слоту (шаг 30 мин), всплывающая шапка выбранного времени (`SelectionTimeHeaderView`) и автоскролл у краёв экрана.
  - Перетаскивание события между днями/временем (long-press + drag, шаг 15 мин) и изменение длительности за нижний handle с оптимистичным обновлением UI.
  - Кнопка быстрого возврата к «Сегодня» (появляется, когда текущий день вне экрана).
  - Переход по клику на месяц → `month` (заглушка), по клику на день → `day` (заглушка).
- `EventEditorView` — базовый sheet-редактор события (название, тип, дата/время, stepper длительности/напоминания, 5 цветов, заметка, удаление).

### Замеченный техдолг в текущем `CalendarIos`
1. **Пересоздание ViewModel в `AppShellView.swift`**: `WeeklyViewModel` создаётся прямо внутри `body`, из-за чего состояние теряется при перестроениях и переключениях режимов. Нужно хранить через `@StateObject` / `@Observable` на уровне shell.
2. **Монолитный `WeeklyView.swift` (2211 строк)**: в одном файле находятся UI, расчёт layout-кластеров, UIKit gesture bridges и scroll observer. Стоит разбить на модули (`WeeklyTimelineLayout`, `WeeklyGestureBridges`, `WeeklyEventBlock`, `WeeklyHeader`, и т.д.) перед добавлением новых фич.
3. **`ScrollViewBridge` с `CADisplayLink`**: постоянный поллинг `contentOffset` на каждом кадре. Лучше заменить на KVO (`observe(\.contentOffset)`) или iOS 17/18 нативные API скролла.
4. **Смешанный язык UI**: в `AppShellView` строки на русском, в `WeeklyView` и `EventEditorView` — на английском. Нужно сразу заложить String Catalog (`.xcstrings`).
5. **Отсутствует test target**: нет юнит-тестов для миграций, репозиториев, генератора повторений, трекеров и расчёта layout.
6. **Устаревшее примечание в `Docs/SETUP.md`**: `xcodegen` уже установлен в системе (`/opt/homebrew/bin/xcodegen`), `.xcodeproj` сгенерирован.

## 3. Сравнение фич: Android vs iOS

| Модуль / Фича | Android (`Calendar`) | iOS (`CalendarIos`) | Примечания по iOS-адаптации |
|---|---|---|---|
| **Weekly View** | Кастомная сетка, 1–10 дней, шаг скролла, зум, drag/resize, long-press create, подсветка сегодня/гайда, дни рождения, трекеры, еженедельные повторения, Copy Mode | Базовая сетка, зум, drag/resize, long-press create, кнопка «Сегодня» | Доделать: отображение повторений, маркеров ДР и трекеров, Copy Mode, настройки сетки (квант, число дней, цвет подсветки, хаптик) |
| **Daily View** | Карточный список дня: трекеры → ДР → события (с опциями и заметками) + блоки «Свободное время» (настраиваемый порог) | Заглушка | Нативный `List` / карточки, свайпы между днями, быстрое добавление, свайп-действия по трекерам/событиям |
| **Monthly View** | Вертикальный бесконечный календарь (`VerticalCalendar`), круговая диаграмма событий в дне (`DayPieChart`), стеки точек ДР и трекеров, подсветка сегодня, клик по месяцу → Год, клик по дню → Неделя/День | Заглушка | Сетка месяцев на SwiftUI (`LazyVStack` + 7-колоночный grid), нативный `Canvas` для мини-круговой диаграммы дня и маркеров |
| **Yearly View** | Сетка 3×4 месяцев на год, стрелки года, цвет доминирующего события в дне, точка ДР, клик по месяцу → Месяц | Нет (нет даже в `CalendarMode`) | Добавить `.year` в иерархию масштабов (Год ↔ Месяц ↔ Неделя ↔ День), адаптивная сетка (3 колонки iPhone / 4 iPad) |
| **Создание событий** | Экран выбора шаблона (`EventCreateScreen`) + кнопки «Создать шаблон» и «Уникальное событие» | Простой `EventEditorView` sheet | Адаптировать под быстрый iOS sheet: быстрый выбор шаблона в 1 тап + сегмент/кнопка «Уникальное событие» |
| **Редактор события (по шаблону)** | Смена шаблона, переход в редактор шаблона, дата/время, длительность, выбор **Опции/Варианта** с авто-длительностью и динамическими полями (`VARIANT_TEXT`, `PHOTO`, `GEO_LOCATION`, `CLIENT`), заметка | Базовый (без опций, динамических полей, быстрого редактирования шаблона) | Поддержать всю систему опций шаблона, `PhotosPicker`, пикер контактов/клиентов, пикер локаций |

## 4. Полная схема данных (Room → GRDB)

Для функционального паритета с Android в GRDB потребуются следующие таблицы (можно добавлять поэтапно миграциями `v2`, `v3`, ...):

1. `event_types` *(есть в v1)* — шаблоны событий (`id`, `title`, `defaultDurationMinutes`, `colorHex`, `notifyBeforeMinutes`, sync fields).
2. `events` *(есть в v1, нужно расширить)* — добавить `audioNotePath`, `selectedOptionId`, `selectedOptionName`, sync fields.
3. `options` — варианты/опции шаблона (`id`, `eventTypeId` FK cascade, `name`, `description`).
4. `option_fields` — поля опции (`id`, `optionId` FK cascade, `fieldType`, `sortOrder`, `label`, `defaultDurationMinutes`, `defaultTextValue`, `defaultLocationId`, `photoPath`).
5. `event_option_values` — значения полей опции конкретного события (`id`, `eventId` FK cascade, `fieldId` FK cascade, `textValue`, `photoPath`, `clientId`, `latitude`, `longitude`, `locationLabel`).
6. `weekly_recurring_events` — еженедельные повторяющиеся события (`id`, `templateId`, `customTitle`, `customColorHex`, `reminderMinutes`).
7. `weekly_recurring_event_slots` — слоты расписания (`id`, `weeklyEventId` FK cascade, `dayOfWeek` 1..7, `startTime` HH:mm, `durationMinutes`, `note`, `sortOrder`).
8. `birthdays` — дни рождения (`id`, `name`, `birthDate` ISO YYYY-MM-DD или `--MM-DD`, `note`, `contactPhone`, `contactId`, `photoPath`, `remindWeekBefore`, `remindAtStart`, `lastAcknowledgedYear`).
9. `trackers` — периодические трекеры (`id`, `name`, `intervalDays`, `createdDateMillis`, `lastResetDateMillis`, `colorHex`).
10. `todo_items` — задачи (`id`, `text`, `isDone`, `createdAtMillis`).
11. `clients` — клиенты (`id`, `name`, `phone`, `email`, `contactId`, `photoPath`, `note`).
12. `location_links` — сохранённые точки/ссылки на карту (`id`, `url`, `title`, `type`).

> **Заметка про синхронизацию**: даже если облачная синхронизация делается позже, имеет смысл сразу заложить опциональные колонки `remoteId` (`firestoreId`), `lastModifiedMillis`, `syncStatus` в новых миграциях, чтобы потом не переделывать схему.

## 5. Принципы iOS-нативности (не 100% клон Android)

- **Навигация**: использовать нативный `NavigationStack`, системные `ToolbarItem`, свайп-назад и `sheet` / `presentationDetents` вместо кастомного `SubScreenTopBar` из Material 3. В `AppShellView` рассмотреть `TabView` (например: Календарь, Задачи, Дни рождения / Трекеры, Ещё) либо компактный верхний бар с настраиваемыми быстрыми кнопками — в зависимости от предпочтений пользователя.
- **Типографика и цвета**: использовать системные семантические цвета (`.systemBackground`, `.secondarySystemBackground`, `.label`, `.secondaryLabel`), поддержку Light / Dark / System из коробки и Dynamic Type.
- **Формы и пикеры**: `Form` с `.insetGrouped`, нативные `DatePicker`, `ColorPicker` (плюс быстрые пресеты), `PhotosPicker`, `CNContactPickerViewController`, `.searchable`, `.swipeActions`, `.confirmationDialog`, `UIImpactFeedbackGenerator` / `.sensoryFeedback`.
- **Удаление Android-специфики**: скрытие системных панелей (status/nav bar), `BatteryOptimizationHelper`, `BootReceiver`, `FullScreenNotificationActivity`, кастомный `WheelPickerCompose` — на iOS не нужны, их заменяют нативные механизмы платформы.

## 6. Предлагаемая поэтапная дорожная карта

### Этап 0 — Фундамент и рефакторинг (быстрый старт)
- Вынести `WeeklyViewModel` из `body` в `AppShellView` (`@StateObject` / `@Observable`).
- Разбить `WeeklyView.swift` на 4–5 логических файлов, заменить `CADisplayLink` на наблюдение `contentOffset`.
- Настроить `Localizable.xcstrings` (как минимум `ru` + `en`, позже остальные языки).
- Добавить Unit Test target в `project.yml` и `Package.swift`.

### Этап 1 — Ядро календаря (все 4 вида + шаблоны + настройки)
- Экран **Шаблонов событий** (CRUD `EventType`) + быстрое создание события по шаблону или как уникальное (поток `EventCreate` → `EventEdit` / `UniqueEvent`).
- **Daily View** (список дня + расчёт свободного времени + перелистывание дней).
- **Monthly View** (вертикальный календарь с круговой диаграммой дня и маркерами).
- **Yearly View** (12 месяцев с цветовыми индикаторами и переходом в месяц).
- **Настройки** (формат 12/24ч, первый день недели, тема, настройки недельного вида: кол-во дней, шаг скролла, квант, цвета подсветки, хаптик, порог свободного времени).
- **Copy Mode** в недельном виде.

### Этап 2 — Продуктивные модули и маркеры в календаре
- **Еженедельные повторяющиеся события** (CRUD со слотами + генерация виртуальных событий во всех видах календаря).
- **Трекеры** (CRUD, Reset, точки в Monthly/Weekly/Daily, уведомление о просроченных при запуске).
- **Дни рождения** (CRUD, импорт из Контактов, фото, маркеры в календаре, отметка поздравления за год).
- **Todo List** (список дел со свайпами и быстрым вводом).

### Этап 3 — Продвинутые функции шаблонов и событий
- **Клиенты** (CRUD + импорт из контактов).
- **Точки на карте** (CRUD + поиск + открытие в картах).
- **Опции шаблонов и их поля** (`OptionEntity`, `OptionFieldEntity`, `EventOptionValueEntity`: текст варианта, переопределение длительности, фото, клиент, геолокация).
- **Аудиозаметки** для уникальных событий (`AVFoundation`).

### Этап 4 — Уведомления, бэкап / синхронизация, полировка
- Локальные уведомления (`UNUserNotificationCenter`) для событий, ДР и трекеров.
- Бэкап/экспорт-импорт JSON и/или облачная синхронизация (Firebase Firestore или iCloud — по решению пользователя).
- Онбординг / подсказки (переиспользование текстов туториалов или TipKit).
- Адаптация под iPad, локализация на остальные языки, тестирование.
